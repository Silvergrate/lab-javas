## Тема та мета

Тема роботи — опрацювання нескінченних послідовностей даних за допомогою Java Stream API, `Optional` і власного `Gatherer`.

Мета роботи — реалізувати сервіс аналізу транзакцій і перевірити, що пошук, вибірка в межах бюджету та групування зупиняють читання нескінченного потоку за відповідною умовою.

## Розрахунок варіанта

Номер варіанта дорівнює остачі від ділення номера залікової книжки на 3. Оскільки `4104 = 3 × 1368 + 0`, маємо `4104 mod 3 = 0`.

## Опис проєкту

Класи розміщено в пакеті `ua.kpi.comsys.streams`. Запис [`Transaction`](src/main/java/ua/kpi/comsys/streams/Transaction.java) містить ідентифікатор `transactionId`, категорію `category`, суму `amount` типу `BigDecimal` і часову позначку `timestamp` типу `LocalDateTime`. Тип `BigDecimal` дає змогу точно додавати десяткові суми та порівнювати їх за числовим значенням.

Клас [`TransactionStreamAnalyzer`](src/main/java/ua/kpi/comsys/streams/TransactionStreamAnalyzer.java) реалізує три операції.

| Метод | Поведінка |
| --- | --- |
| `findFirstHighValueTransaction(stream, threshold)` | Фільтрує транзакції за умовою `amount > threshold`. Операція `findFirst()` зупиняє читання на першому збігу та повертає `Optional<Transaction>`. Якщо скінченний потік вичерпано без збігів, результатом є `Optional.empty()`. |
| `takeTransactionsUntilBudgetExceeded(stream, maxBudget)` | Послідовно обчислює накопичену суму й повертає початковий відрізок потоку, для якого вона не перевищує бюджету. Рівність бюджету дозволено. `takeWhile()` зупиняє читання на першій транзакції, яка спричинила перевищення, та вилучає її з результату. |
| `processBatches(stream, batchSize, maxBatches)` | Формує до `maxBatches` пакетів по `batchSize` транзакцій у порядку надходження. Якщо скінченний потік завершується посеред пакета, неповний пакет пропускається. |

Для вибірки за бюджетом `Gatherers.scan` послідовно обчислює накопичену суму та пов’язує її з поточною транзакцією. Операція `takeWhile()` порівнює цю суму з бюджетом, після чого `map()` повертає лише транзакції. Транзакції з від’ємними сумами зменшують накопичену суму до моменту першого перевищення бюджету. [Документація Java SE 24 для `Gatherers.scan`](https://docs.oracle.com/en/java/javase/24/docs/api/java.base/java/util/stream/Gatherers.html).

Групування реалізовано через `Gatherer.ofSequential`. Стан операції зберігає поточний пакет і кількість переданих пакетів. Після заповнення пакета інтегратор передає копію списку в наступний етап потоку й очищує буфер. Після формування останнього дозволеного пакета інтегратор повертає `false`, тому читання джерела припиняється без запиту додаткової транзакції.

Значення `null` замість потоку або обов’язкового аргументу та непозитивні `batchSize` і `maxBatches` спричиняють `IllegalArgumentException`. На нескінченному потоці пошук завершується за наявності збігу, а вибірка за бюджетом — після першого перевищення. За відсутності відповідної події ці операції продовжують читати джерело.

## Демонстраційний запуск

Клас [`Main`](src/main/java/ua/kpi/comsys/streams/Main.java) для кожної операції створює новий нескінченний потік із сумами 10, 20, 30, 40 і далі.

| Операція | Параметри | Результат |
| --- | --- | --- |
| Пошук першої транзакції понад поріг | Поріг 20 | `T-3`, сума 30 |
| Вибірка в межах бюджету | Бюджет 60 | `T-1`, `T-2`, `T-3`. Накопичена сума дорівнює 60. |
| Пакетна обробка | Розмір 2, ліміт 2 | `[[T-1, T-2], [T-3, T-4]]` |

Для виведення результату пошуку використано функціональні методи `Optional`.

## Запуск і тестування в IntelliJ IDEA

Для роботи потрібен JDK 24 або новіший, наприклад JDK 25. Проєкт компілюється з параметром `--release 24` і використовує стабільний API Stream Gatherers. Збірку налаштовано через Gradle Wrapper, а версії тестових залежностей визначено в [`gradle/libs.versions.toml`](gradle/libs.versions.toml).

1. У меню **File → Open** вибрати кореневу папку проєкту `lab3-transaction-streams` з файлом `build.gradle`.
2. Дочекатися синхронізації Gradle. За потреби вибрати встановлений JDK 24 або 25 в полі **Gradle JVM** за шляхом **Settings → Build, Execution, Deployment → Build Tools → Gradle**.
3. У вікні **Gradle** запустити **Tasks → verification → test**. Для запуску програми відкрити `Main.java` і натиснути зелену стрілку біля методу `main`.

У Linux і macOS тести також можна запустити з кореня проєкту командою `./gradlew test`, а демонстрацію — командою `./gradlew run`. HTML-звіт Gradle після запуску тестів доступний у `build/reports/tests/test/index.html`.

Тести [`TransactionStreamAnalyzerTest`](src/test/java/ua/kpi/comsys/streams/TransactionStreamAnalyzerTest.java) написано з використанням JUnit 5. Вони перевіряють поведінку на скінченних і нескінченних потоках, граничні значення та обробку некоректних аргументів. Сценарії з нескінченними джерелами мають двосекундний тайм-аут і перевіряють кількість фактично прочитаних елементів.

**Результат перевірки:** на JDK 25 успішно виконано всі 19 тестових сценаріїв, зокрема три на нескінченних потоках. Демонстраційний запуск дав результати, наведені в таблиці.

## Висновок

Реалізовано сервіс аналізу транзакцій, у якому `findFirst()` і `takeWhile()` обмежують читання умовами пошуку та бюджету, а власний `Gatherer` завершує пакетну обробку після досягнення заданого ліміту. `Optional` представляє відсутність результату пошуку після вичерпання скінченного потоку.
